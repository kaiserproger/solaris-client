## Changes and remaining boundary

- Fixed physical inventory/container UI routing in `src/lib.rs`: visible cursor on opening, pointer motion, distinct physical press/release edges for drag, Shift-click modifier delivery, and no gameplay movement/drop/hotbar-wheel leakage while a menu is open. Dialog buttons keep their previous synthesized Down+Up behavior.
- Added a Loading screen/readiness gate in `src/session/observation.rs`: play observation and terrain submission wait for spawn pose, both received light channels, and nearby chunk/biome data; screen transition releases held gameplay input. Loading owns input until ready. Added spawn-readiness and loading-UI regression tests.
- `minecraft_wait_for_play` now uses the same received-world readiness predicate as `in_play`, so a phase transition alone cannot release the Title flow into gameplay before the client can present the world.
- `PLAYING.md` now documents UI slot clicks, right-click stack split, Shift-click quick-move, and hold-and-drag distribution.
- Ordinary Solaris survival is available with the explicit `offline-test` profile. Official Microsoft authentication remains a known limitation; it does not block connecting to the configured offline/test Solaris server.
